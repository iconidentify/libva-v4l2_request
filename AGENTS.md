# Instructions for coding agents

Read README.md, CONTRIBUTING.md and docs/CONTRIBUTOR_START.md before changing this
unofficial fork. The live execution/claim authority is
https://github.com/iconidentify/libva-v4l2_request/issues/8; the roadmap is issue #7.

- Start from the current `avd-fixes` branch in an isolated checkout/worktree. Read
  the entire ready leaf, native dependencies, comments and open PRs; claim one
  bounded scope with a unique session ID and recheck for collisions before editing.
- Offline work needs no Apple hardware or installation. Build the Linux V4L2 driver
  on Linux; source/Python tasks can use other suitable hosts. Use the task-specific
  checks plus applicable CONTRIBUTING.md validation. Do not claim a test ran when
  the required environment was unavailable.
- Preserve contributor authorship and raw evidence. Model tests, software fallback,
  safe rejection and hardware output are different results. Retain exact pass sets
  and full denominators; close a parent only after all its criteria are delivered.
- Coordinate shared files and respect active claims. Open a scoped draft PR, give
  exact validation/limitations, disclose AI-authored prose as required, and record
  whether review was independent. Do not bypass required CI or branch protection.
- Hardware commands require the portable guard, an exclusive window, finite
  deadlines and durable provenance. The companion repository's AGENTS.md and README
  govern Apple machine checks, kernel/install/module/boot authorization and recovery.
  Never remove a guard, edit shipped kernel patches or reset a decoder to make a
  source-only task pass. A previous experiment's authorization is not a new lease.
- Keep routine reports and dependency patches in these forks. No upstream reports
  or social posts are implied by an issue claim. Release or renew the claim and
  leave a concrete handoff when stopping.

## M1 delivery priority and shared desktop builds

Follow the companion [current delivery plan](https://github.com/iconidentify/omarchy-m1-video/blob/main/docs/M1_DELIVERY.md)
and the live roadmap before choosing new owner-directed work. Preserve existing
claims. On the shared desktop, invoke the companion `tools/bounded-build` from
this checkout for builds/CPU tests; pass one worker. Finish that fixed-name job
before acquiring the separate hardware guard. Do not raise limits or delete
retained evidence to make a run pass. Portable/off-host CI stays unchanged.
