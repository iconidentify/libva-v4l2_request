# Contributing

Help us make a scoped change with reproducible evidence. Read the [README](README.md),
applicable AGENTS.md files and [agent workflow](docs/AGENT_WORKFLOW.md) before starting.
The [live workflow](https://github.com/iconidentify/libva-v4l2_request/issues/8) controls claims and completion; this guide does not replace it.
Suspected vulnerabilities follow [SECURITY.md](SECURITY.md), not the public bug form.

## Find a bounded contribution

Start with [the contributor entry point](docs/CONTRIBUTOR_START.md) for offline
codec and AVD work, required skills, live ready queues and a copyable agent prompt.
Apple hardware is not required for these offline tasks. Each child has its own
acceptance criteria; hardware qualification remains in its parent.

## Choose the owning repository

| Change or report | Repository |
| --- | --- |
| VA-API negotiation, V4L2 request handling, codec parsing, surfaces, driver regressions | [libva-v4l2_request](https://github.com/iconidentify/libva-v4l2_request), base `avd-fixes` |
| Installer, packaging, rebuild hooks, boot behaviour, system/client/display qualification | [omarchy-m1-video](https://github.com/iconidentify/omarchy-m1-video), base `main` |

Record kernel, client and display dependencies in the companion repository with exact
external revisions. Keep routine reports in these forks. Do not send setup reports
upstream or add a generic driver workaround for a problem owned by another layer.
Preserve the credits and licences in each repository when importing work.

## Claim and isolate the change

Pick one ready leaf ticket, read its full discussion, native dependencies and linked PRs,
then follow the live workflow's unique-session claim and collision check. Assignment
alone does not reserve work. Check the working tree is clean and preserve existing edits.

For a new contributor, fork this repository on GitHub, then replace `YOUR_LOGIN` below.
Choose a unique branch name instead of reusing another contributor's branch.

```sh
git clone https://github.com/YOUR_LOGIN/libva-v4l2_request.git
cd libva-v4l2_request
git remote add upstream https://github.com/iconidentify/libva-v4l2_request.git
git fetch upstream
git switch -c contribution-topic upstream/avd-fixes
```

An existing checkout can use a dedicated worktree instead. Include the actual base SHA,
branch, local path and primary files in the claim. Coordinate changes to shared files.
Contributors without issue-edit permission should record progress in comments and ask
a maintainer to reconcile assignment and labels.

## Run the offline checks

Use Linux with a C compiler, Meson, Ninja, pkg-config, Linux UAPI headers, libva and libdrm
development files. The software frame checks also need FFmpeg and its libavformat,
libavcodec, libavutil and libswscale development files. The dependency installation used by
CI is in [.github/workflows/checks.yml](.github/workflows/checks.yml). Native macOS cannot
build the Linux V4L2 driver; report that limitation and use Linux CI.

Run from the repository root. Use a fresh build directory for the driver.

```sh
meson setup build-contrib -Db_sanitize=address,undefined
meson test -C build-contrib --print-errorlogs
sh tests/frame-check.sh
sh tests/shared-contexts.sh
```

See [tests/README.md](tests/README.md) for the detailed test contract. Record commands, tool versions,
source SHA, results and checks not run with reasons. The driver shell commands above
use software because no driver-directory argument is supplied. Hardware validation
requires a separate guarded lease and is not implied by an offline pass.

For documentation and template changes, check local links and YAML structure, then
walk through the public-report and private-report routes with synthetic data. Do not
file synthetic issues or send test reports to maintainers. Retain the existing CI check.

## Prepare a reviewable PR

Follow surrounding C, shell and Python style. Keep backend quirks in their owning layer,
and add a relevant regression for a behaviour change. Avoid unrelated formatting edits,
blanket warning/sanitizer suppressions and changes to expected output that conceal failures.

Push your branch to your fork and open a draft PR targeting `avd-fixes` in this repository.
Use the [PR template](.github/PULL_REQUEST_TEMPLATE.md). Explain the trigger, before/after
behaviour, acceptance evidence, dependencies and limitations. Link the companion PR for
changes spanning both repositories. Use `Refs` while integration criteria remain unmet.

Every AI-authored PR title/description must carry this visible disclosure:

> This pull request, including its title and every word of this description, was generated by AI.

Describe AI assistance accurately for mixed authorship. Retain original commit authors,
licence notices and attribution for imported changes; identify their source revisions.
Do not put private media, URLs, credentials, core dumps or unrelated logs in the PR.

Maintainers select and record a reviewer with knowledge of the changed layer. Seek an
independent reviewer for security and shared lifetime/reference changes; identify a
self-review honestly. A green check does not demonstrate independent review or missing
hardware evidence. See [maintenance and handoff](docs/MAINTENANCE.md) for the release decision.

## Hardware and system boundaries

Use the driver repository's `tests/hwguard.py` for hardware commands, with a finite deadline,
an idle/fault preflight and an idle final state. Stop after a new fault or wedge.
Do not automatically unload a module or repeatedly reopen a stuck decoder.
The companion [AGENTS.md](https://github.com/iconidentify/omarchy-m1-video/blob/main/AGENTS.md)
and README control supported-machine checks, informed installation consent, saved work
before module unload/reboot, and recovery. Shipped kernel patches are not editable under
the standing instructions. Keep mpv on OpenGL. Public PR CI must not expose a self-hosted
hardware runner, host access or secrets to untrusted code.
